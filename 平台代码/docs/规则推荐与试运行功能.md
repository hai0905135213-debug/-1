# 规则推荐与试运行功能

本轮实现可解释的规则匹配、课表空闲推荐、15分钟限时招募、履约记录与商家优惠信息。保留原版网页设计，不建设自动派单、自动教务登录、数值信用惩罚、支付或核销。

## 使用入口

原版网页首页新增“为我推荐”“商家优惠”；登录后“我的”新增课表、履约入口；管理员另有优惠管理。发布饭局可选择预约或限时15分钟招募。小程序源码同步增加 `pages/discovery/index` 及入口，本轮不做微信编译、真机、部署和发布。

## 推荐依据

饭局先排除非所选校区、已加入、本人发起、被拒绝、已截止、与已确认课表及本人已加入饭局冲突的项目，再按以下规则相加：仍可申请10分、同校区20分、预算重叠15分、命中口味20分、共同话题15分、聊天模式一致10分、已确认课表未发现冲突10分。最高100分，是规则排序分，不是匹配成功概率。每项得分附理由，不使用模型猜测忌口或清真要求。

餐厅结合距离、明确口味、想去清单、去过记录排序。空闲窗口明确时采用粗估：往返直线距离按4km/h步行，加用餐30分钟及缓冲15分钟；超出窗口或缺少距离的项目不作“来得及”推荐。该估算不是导航耗时，不包含排队、实际路线、出餐时间，页面会明确提示。没有价格数据不会伪造预算命中。

## 课表

支持文字PDF导入，8MB以内；扫描图片暂不支持OCR。导入结果需用户逐条核对课程、星期、节次、周次与单双周，并确认第一周周一日期及节次起止时间后才启用。示例节次不是学校官方作息。新导入或修改课程使旧确认失效；未导入/未确认/学期范围外不声称已确认空闲，可以手动填写空闲分钟。

周次默认从第一周周一计算，最多30周，支持1–16节、周一至周日及显式周次。缺周次时保守按每周处理并提示，临时调课不自动同步。不收集教务账号密码，不保留上传PDF原件。当前PDF解析以文字行格式为主，复杂表格可能需要手动修正，不能保证自动识别所有学校格式。

## 限时招募

`recruitMode=limited` 的截止由服务器设为发布后15分钟与就餐时间中的较早者，不能由客户端延长。仍需发起人审批；到期不允许申请/审批，未处理申请在请求时自动关闭。不依赖只存在于浏览器的倒计时，也不把过期饭局自动标记成已就餐或取消。没有实时派单、微信订阅推送和自动拉群。

## 履约

展示本人完成组队、退出、发起后取消、收到评价以及到场自报的真实记录。正式成员可在就餐前30分钟至开始后4小时自报到场，每场幂等保存一次。自报不是GPS/第三方核验，完成饭局也不证明所有人实际到场。首版不自动加减信用分、不凭单方举报处罚，不提供虚假的履约率。

## 优惠信息

管理员选择真实餐厅，填写标题、说明、HTTPS来源、核验备注及有效期；明确确认核验后才能发布。草稿、到期、未开始或已下架的信息不出现在公共列表。不创建演示优惠，不收款、发券、核销、退款、抽佣或结算，最终条件以商家确认为准。

## 新接口

| 接口 | 用途 |
| --- | --- |
| GET /api/discovery/recommendations | 登录后获取规则推荐；campus/freeMinutes/duration/topics/chatMode/at可选 |
| GET 与 PUT /api/schedule/settings | 本人学期、节次与确认状态 |
| POST /api/timetable/import | 校验并保存本人课程，撤销原课表确认 |
| POST /api/timetable/pdf-import | 上传pdfBase64/fileName，识别后需核对 |
| GET /api/profile/fulfillment | 本人履约记录，before游标分页 |
| POST /api/meals/:id/check-in | 正式成员本人到场自报 |
| GET /api/offers | 游客可读有效优惠，支持restaurantId |
| GET 与 POST /api/admin/offers | 管理员查看及录入信息 |
| POST /api/admin/offers/:id/archive | 管理员下架 |

数据库迁移版本4，迁移前SQLite在线备份。业务库及备份不提交Git，餐厅仓仍独立只读。

## 验证

后端运行 `npm run check` 与 `npm test`，包括课程周次/单双周/星期日/边界、非法节次、未确认课表、冲突硬排除、限时截止、到场自报窗口及幂等、管理员权限、优惠有效期和下架。项目根目录运行 `node scripts/verify_original_ui.mjs` 验收原版界面，使用隔离浏览器和临时业务库，包含实际PDF上传、课程核对、规则推荐及优惠管理，不向日常数据写测试内容。
