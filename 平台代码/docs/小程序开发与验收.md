# 饭饭之交小程序开发与验收

本轮目标是本地可构建、可联调的预约组队版本。微信小程序页面为 `frontend/pages/`，使用 Vue 3 和 uni-app。

网页主预览 `frontend/preview-static/` 保留原版设计，通过 `integration.js` 接入同一后端；`npm run preview:web`、`npm run preview:static` 启动它。`npm run dev:h5` 则运行正式小程序源码的H5调试版，二者不是同一个前端实现，不能用网页通过代替小程序验收。

2026-10-22 根据实际微信截图反馈，将原版网页视觉移植到小程序的首页、找人、动态、个人页、发布、餐厅详情、饭局详情和我的饭局；统一白底/深色标题/黄色操作、蓝绿色个人页、专辑与横排餐厅卡片、图标底栏和中央发布按钮。功能继续使用原接口。小程序的胶囊/导航、原生picker等需适配平台，不承诺逐像素完全一致；微信工具和真机仍须本机核验。

新增 `scripts/verify_uni_ui.mjs`，专门验收同一套小程序源码的H5渲染、截图和真实接口交互，而非原网页；临时业务库、独立浏览器，不写日常数据。默认连接 `http://127.0.0.1:5180/`，可用 `UNI_H5_URL` 覆盖。运行前在frontend执行 `npm run dev:h5 -- --port 5180`。这依然不代替微信设备测试。

当前运行地址：原版网页 `http://127.0.0.1:5174/`，小程序H5调试 `http://127.0.0.1:5173/`。命令默认端口为5173；同时运行时用 `PORT=5174 npm run preview:web`。

原版接入验证脚本：在项目根目录运行 `node scripts/verify_original_ui.mjs`。使用临时业务库与隔离浏览器，不修改日常数据；涵盖原界面搜索、分店发布、白名单、申请撤回、审批、通知、留言、退出、拒绝、完成评价与取消。详细结果以脚本实际输出为准。

## 启动

建议 Node.js 22，依赖使用对应目录里的 package-lock.json 安装。

后端：

```bash
cd 平台代码/backend
npm ci
ENABLE_DEV_LOGIN=true ADMIN_USER_IDS=1 npm start
```

首次本地开发时，第一个新建的测试用户编号通常为 1。已有业务库请先确定自己的用户编号，再填写 `ADMIN_USER_IDS`，不要把其他人的编号设为管理员。管理员身份和体验资格由服务端配置授予，客户端不能自行提权。普通登录用户默认没有组队资格，管理员通过“我的 → 体验资格和举报管理”批准。

新版会话不兼容旧 `dev-token-*`，旧网页用户需要重新登录。开发登录只在 `ENABLE_DEV_LOGIN=true` 且非生产环境生效。

同一套正式页面的网页调试：

```bash
cd 平台代码/frontend
npm ci
npm run dev:h5
```

本地开发配置 `.env.development` 使用 `http://127.0.0.1:3001/api`。复制 `.env.example` 为本地配置后可修改地址；真机上的 127.0.0.1 指手机自己，真机联调需要填写开发电脑的可达地址。生产构建默认不显示开发登录。

微信小程序构建：

```bash
npm run build
```

在微信开发者工具导入 `frontend/dist/build/mp-weixin`。项目尚无真实 AppID，manifest.json 的 AppID 留空；申请 AppID 后填写 `mp-weixin.appid`，真实登录所需的 AppSecret 只配置到后端环境变量。不要在前端写密钥。

## 已实现流程

餐厅发现支持名称、分店、地址、菜系、推荐菜搜索；输入防抖300毫秒，切换查询条件会丢弃旧请求。品类多选取并集，标签多选取并集，不同维度交叉筛选。可按两校区或全校距离、群聊热度查询；首页每批6家，完整餐厅列表每批12家。距离均为直线距离。无已确认数据时不展示虚构价格、评分或口味标签。

餐厅详情支持分店选择、地址、地图、双校区距离、推荐菜、预约提示、想去和去过。从选定分店发起饭局，会将餐厅字符串ID、POI ID、分店名称、地址和坐标写入饭局快照。日后切换校区不会改动已发布地点。

预约饭局人数为2–12人，发起人计入人数。待审批不占名额；发起人通过后加入。满员自动成局并关闭剩余申请，成员退出后重新开放，旧申请不自动恢复。拒绝者本场不可再申请，撤回者可重新申请。报名截止后不能申请或审批。首版发布后不修改关键条件，需要变更时取消并重新发布。

只有正式成员能读取集合说明和队内文字留言；退出后不可读写。留言每条最多500字、按游标分页，页面前台打开时每5秒刷新。结束后留言只读。发起人可取消；就餐时间到达且至少2名正式成员时可完成。完成后成员才能互评，每人每场对同一队友只能评价一次，不可自评。举报进入管理员列表，不自动扣信用分。

“找人”显示可申请饭局和帖子。新帖子必须关联发起人自己的饭局，报名统一进入饭局审批；未关联的历史帖子只展示，不再直接加入另一套队伍。

## 数据与兼容

- 业务库默认仍在 `backend/data/fanfan.db`，餐厅仓默认仍在项目根目录 `database/data/restaurants.db`。
- 可分别通过 `DATA_DIR` 和 `RESTAURANT_DB_PATH` 指定路径。
- 新增版本化迁移，执行新迁移前在业务数据目录 `backups/` 保留快照；不清空旧记录。
- 新会话只存Token哈希，7天过期、退出可撤销。`X-User-Id` 和旧开发Token不再作为登录依据。
- 新的餐厅收藏和去过记录保留字符串ID；历史数字ID继续兼容。纯名称历史记录保留原名称。
- 教务代理入口默认关闭，需单独设置 `ENABLE_TIMETABLE_PROXY=true` 才开放，不影响组队。

真实 AppID、真实微信登录、开发者工具导入后的设备兼容、真机网络及地图表现仍需在外部条件就绪后验收。本轮不部署服务器，不配置域名/HTTPS，不上传体验版或提交审核。
